**Horizon**: Breaks when adding MCP sampling, roots, or tool-list-changed refresh

The `McpConnectionManager` singleton pattern works for current scope, but adding MCP sampling support (server-initiated LLM calls through the client) or live tool-list-changed refresh would require splitting connection management from capability orchestration.

## Novel Perspective

### The Passion-Junior Pipeline Has Become a Load-Bearing Architecture Validator

**Why no one has seen this**: Previous reviews identified passion-junior as an "enforcement mechanism" (2026-06-25 review), but that framing understated its structural role. It's not just enforcing tech-lead recommendations — it's the only mechanism that tests whether the codebase can absorb independently-scoped changes without coordination overhead.

**Evidence**: 6 of 61 commits in this cycle came from github-actions[bot] (passion-junior), executing 5 of the 7 open issues from the previous review. Each was an independent PR touching 1-4 files, merged without conflicts or rework. Meanwhile, 4 human contributors committed 55 changes across overlapping subsystems (web, runtime, protocol) in the same 8-day window — also with zero conflicts or reverts.

**Implication**: The absence of merge conflicts across 4 contributors + 1 bot in a 61-commit window is not luck — it validates that the package boundaries and handler decomposition genuinely create independent work streams. However, this property is invisible and untested: there's no structural enforcement preventing a handler file from importing another handler's internal state, or a web hook from reaching into another hook's private state. The architecture works through convention, not constraint. If the team grows beyond 5-6 concurrent contributors, consider adding package-internal linting rules (e.g., eslint `no-restricted-imports` or biome equivalents) to make the independence guarantees explicit.
