**Impact**: Positive

The `read_image` tool (`packages/runtime/src/tools/read-image.ts`, 227L) and blob sidecar (`packages/runtime/src/session/image-sidecar.ts`, 105L) demonstrate good architectural judgment:

- Session files stay compact via `blob:{sha256}` references externalized to disk
- Backward-compatible: literal base64 entries pass through untouched
- Fallback: missing blobs produce a transparent 1px PNG instead of crashing

## Forward Compatibility

### Auth Structure Will Strain With More OAuth Providers
**Horizon**: Breaks when 2+ additional OAuth providers are added

`packages/runtime/src/auth/` contains 6 files with ChatGPT-specific OAuth handling (callback-server.ts, browser.ts, chatgpt-oauth.ts). The current pattern is one-off: if Gemini, Grok, or other providers add OAuth flows, there is no routing/registry abstraction to handle multiple concurrent OAuth flows. Each would need its own callback server, browser launcher, and token exchange logic.

The cheaper fix now: extract an `OAuthFlowRouter` that parameterizes the provider-specific parts (token endpoint, scopes, PKCE config) while sharing callback server and browser launch infrastructure.

### Tool Catalog Resolution Pipeline Approaching Capacity
**Horizon**: Breaks when remote tool sources or per-session tool overrides are needed

`packages/runtime/src/tools/catalog.ts` (418L) is a monolithic resolution function that handles built-in tools, plugins, bundled providers, conflict resolution, toggle application, and immutability enforcement in one pass. The `supersedesPluginPackages` field in BundledToolProvider already adds conditional logic. Adding remote tool registries, per-session tool overrides, or tool capability negotiation would require significant refactoring.

A phase-based pipeline interface (load → merge → resolve → filter → freeze) would make each stage independently testable and extensible.

### Provider Implementation Diversity
**Horizon**: Maintenance cost compounds with each new model capability

8 LLM providers exist with per-provider message conversion logic. Recent additions (image support in 6527afd, thinking effort, web fetch results) required touching 5-8 provider files each. The `openai-compatible.ts` extraction (#125) and `openai-shared.ts` decomposition help, but each new model capability (tool streaming, structured output, citation formats) still requires per-provider implementation.

No immediate action needed — the current provider count is manageable — but a shared `ProviderAdapter` pattern that handles common conversion (messages → provider format, provider events → AgentEvent) would reduce per-provider boilerplate.

## Novel Perspective

### The Fix-to-Feature Ratio Reveals a Phase Transition Signal

- **Why no one has seen this**: Previous reviews focused on architectural structure and package coherence. Commit-type ratios were mentioned descriptively but not analyzed as a predictive signal. The 57% fix ratio in this cycle is the highest observed across all reviewed periods.

- **Evidence**: 29 fixes vs 16 features in 51 commits. Fixes cluster temporally after features:
  - `read_image` (6527afd) → 2 follow-up fixes (read-image.test.ts additions in 86e1a52)
  - ChatGPT auth (aa244dc, 194bfc0) → 4 follow-up fixes (88ae90d, f6c00a1, 607e54a, d432b66)
  - Bundled providers (93f0bd3) → follow-up fix (4ab8075 scoped model selection)
  - Error handling (84d6548) → follow-up fix (972f60a sanitize network errors)

  Each new capability generates a "fix tail" of 2-4 hardening commits. At current feature velocity (~1 major feature per week), this produces a sustained ~2:1 fix-to-feature ratio.

- **Implication**: This is not a bug — it is a signal that the system has reached sufficient user-facing complexity that each capability needs a stabilization period. The project should explicitly plan for "hardening sprints" after major features rather than treating fixes as interrupts. If the ratio stays above 60% for two consecutive review cycles without corresponding feature output, it would indicate genuine architectural friction rather than healthy stabilization.
