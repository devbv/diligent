## Structural Integrity

### Streaming State Is the Next Internal Seam
**Impact**: Compounds over time

The Responses path keeps text, thinking, current tool identity, tool argument buffers, usage, stop reason, completed-response fallback state, and provider-native web blocks in one mutable `ResponsesAPIState` (`packages/core/src/llm/provider/openai-sse.ts:20-30, 56-69`). `reduceResponsesAPIEvent()` then combines generic lifecycle accumulation with Responses-specific web-tool and failure semantics (`packages/core/src/llm/provider/openai-sse.ts:152-288`), while `handleResponsesAPIEvents()` separately owns completion detection and terminal flushing (`packages/core/src/llm/provider/openai-sse.ts:653-702`).

The Chat Completions path independently implements the same generic mechanics for text, thinking, fragmented tool arguments, usage, and terminal message assembly inside `handleChatCompletionsEvents()` (`packages/core/src/llm/provider/openai-compatible.ts:156-275`). The duplication is not a reason to unify wire events: Responses completion events, provider-native web blocks, Chat Completions deltas, and ChatGPT transport behavior are materially different.

**Cheaper fix now**: characterize lifecycle invariants, then extract only a small internal accumulator for text/thinking/tool-call buffering and terminal flush. Keep event decoding, Responses fallbacks, web-tool normalization, retry classification, and WebSocket transport provider-local. Do not create a generic provider stream framework.

### Anthropic Message Conversion Mixes Four Policies
**Impact**: Compounds over time

`convertMessages()` currently performs compaction-summary injection, image materialization and content conversion, tool-result coalescing with image handling, and cache-breakpoint placement in one pass (`packages/core/src/llm/provider/anthropic.ts:191-263`). The same file then carries provider-native replay conversion in `convertAssistantContentBlock()` (`packages/core/src/llm/provider/anthropic.ts:335`) and native-compaction normalization in `ensureAnthropicCompactionConversationEndsWithUser()` (`packages/core/src/llm/provider/anthropic.ts:278-297`). The empty conditional at lines 294-295 is a small but concrete residue of accumulated control flow.

These are all legitimately Anthropic-owned semantics; moving them to a shared cross-provider converter would hide important differences such as signed thinking blocks, server tool replay, image-bearing tool results, and cache-control placement.

**Cheaper fix now**: preserve the exported `convertMessages()` contract, but decompose it into pure provider-local stages for compaction prefixing, per-role conversion, adjacent tool-result coalescing, and cache breakpoint tagging. Add direct invariant tests before rearranging the pipeline.

## Forward Compatibility

### New Stream Events Will Stress Temporal Invariants Before Type Boundaries
**Horizon**: Breaks when an OpenAI-family endpoint adds another partial block, terminal fallback, or interleaved tool event

The Responses reducer already coordinates ordinary content, provider-native web tools, completed-response fallbacks, and explicit failure events (`packages/core/src/llm/provider/openai-sse.ts:171-287, 448`). Chat Completions has a different decoder but the same need to flush pending thinking, text, and tool calls exactly once (`packages/core/src/llm/provider/openai-compatible.ts:242-274`). Without an explicit lifecycle primitive, each new event type forces contributors to rediscover ordering rules inside large provider functions.

The cheap fix is an internal state-transition API with behavioral tests. The expensive future fix would be debugging event-order regressions across HTTP, SSE, and WebSocket after more event kinds have accumulated.

### Anthropic Policy Additions Will Keep Expanding One Conversion Pass
**Horizon**: Breaks when Anthropic adds another provider-native replay block, cache policy, or compaction rule

The current conversion pass is correct but has no stage boundary for applying or testing one policy independently. Pure local stages make future additions additive while preserving Anthropic's distinct wire semantics.

## Novel Perspective

### The Missing Abstraction Is Temporal, Not Provider-Shaped
- **Why no one has seen this**: recent reviews correctly focused on package ownership and transport defects, while source and tests are organized by provider names. That makes duplicated time-order rules look like unrelated provider code.
- **Evidence**: Responses and Chat Completions have different wire decoders but both accumulate partial thinking, text, tool arguments, usage, and a terminal assistant message (`packages/core/src/llm/provider/openai-sse.ts:20-30, 653-702`; `packages/core/src/llm/provider/openai-compatible.ts:162-168, 240-274`). Anthropic conversion shows the complementary problem: semantically distinct policies are hidden inside one sequential pass (`packages/core/src/llm/provider/anthropic.ts:191-263`).
- **Implication**: refactor around lifecycle transitions and transformation stages, not a provider inheritance hierarchy. Shared code should be earned by identical semantics; provider-specific decoding and policy should remain explicit.
